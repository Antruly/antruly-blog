## 为什么又开了一个博客

理由说出来有点老套：碎片化的东西攒多了需要有个地方放。

散落在 GitHub README、issue 评论、聊天记录里的技术结论，过半年自己都找不回来。而写下来的过程本身也有价值——很多「我觉得我懂了」的东西，一旦要落成文字，就会发现某个环节其实没想清楚。

## 为什么是静态站点

我是一个写 C++ 的，日常和 libuv、epoll、内存分配打交道，按理说更该自己写个后端。但这个站的第一版没有后端，理由很直接：

**博客的大部分内容是不变的。** 一篇文章一旦发布，它就是一坨不会变的 HTML。给它配一个数据库、一个应用服务器、一套进程管理，是在给自己制造运维负担——晚上十一点数据库连不上的时候，你并不会因此觉得站点更专业。

所以这站是**构建期生成**的：文章在构建时渲染成静态 HTML，没有运行时数据库，没有服务端渲染。带来的直接好处是：

- 打开快（就是 CDN 发文件）
- 没有「后端挂了站就打不开」这种状态
- 迁移成本极低，产物就是一堆文件

## 用了什么

| 层 | 选型 |
|---|---|
| 框架 | [Astro](https://astro.build/)（静态站点生成） |
| 主题 | [Firefly](https://github.com/CuteLeaf/Firefly)（基于 Fuwari 的二次开发） |
| 样式 | Tailwind CSS v4 |
| 交互 | Svelte 岛（局部水合）+ Swup 无刷新切页 |
| 搜索 | [Pagefind](https://pagefind.app/)（纯客户端全文索引） |
| 评论 | Giscus（挂在 GitHub Discussions 上） |
| 部署 | Cloudflare Workers 静态资源 |

几个我比较喜欢的点：

**全站配色靠一个变量。** 主题把颜色写成 `oklch(... var(--hue))`，改 `--hue` 一个数就能换整站色调，而且因为用的是 oklch，换色时各个颜色的感知亮度是一致的，不会有的色忽然显得刺眼。右下角的显示设置面板里可以自己拖。

**搜索没有服务端。** Pagefind 在构建时把文章切成片段建索引，浏览器加载一段 JS 就能搜全文。省掉了一个搜索服务。

**切页不刷新。** Swup 拦截站内链接，只替换内容容器，配合预加载，页面切换是即时的，但底层仍然是普通的多页静态站——不是 SPA，不会被路由问题折磨。

## 关于后端

前面说了第一版没有后端，但也不是永远不要。

这个站前端有一层统一的接口抽象，所有动态数据都走同一个约定。将来要把某些能力搬到自有后端时，只要那台机器按同一套接口应答，前端一行不用改。

而后端我打算用自己的 C++ 网络库 [libuvcpp](https://github.com/Antruly/libuvcpp) 来写。

为什么不是现在？因为 **Cloudflare Workers 跑不了原生 C++**。Workers 的执行环境是 V8 isolate，只接受 JavaScript 和 WebAssembly，没有原生二进制、没有监听套接字。libuv 依赖 epoll/kqueue、线程和阻塞文件 IO，这些东西也编译不进 WASM。所以 libuvcpp 注定要跑在我自己的机器上，通过隧道把接口暴露出去——这是第二阶段的事。

第一阶段先用 Worker 的 JavaScript 顶替，把接口契约定下来。**先让站能跑、能发文章，比先纠结后端用什么写重要得多。**
